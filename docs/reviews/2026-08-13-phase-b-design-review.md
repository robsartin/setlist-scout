# Phase B clean-design / SOLID / TDD review (#95)

Holistic design + test-quality review of the Phase B modulith + event-driven code (source ports/adapters, `ArtistActivationService`, `shared.events` + `@ApplicationModuleListener` flows, the `scan_job`/`expand_job` model + pollers + backfill), as it stands on `main` after PR1–PR4b, the #96 UI split, and #93 dead-code removal. Two read-only review passes (design/SOLID + TDD/test-quality) informed this.

**Headline: the design is largely sound and unusually well-documented.** OCP for sources is genuinely open/closed (drop in a `@Component` adapter; no `instanceof`/`switch` on source types), DIP is clean (constructor injection throughout), the poller concurrency model (claim-lease `FOR UPDATE SKIP LOCKED` + `@Version` optimistic reschedule) is coherent, and the two hard-won transaction-boundary rules are honored almost everywhere. The findings below are a small number of real issues, not a redesign.

## The event & durable-write invariant (to prevent regressions)

This is the load-bearing rule the whole event design rests on. It belongs in `shared/events/package-info.java` and is recorded as an ADR.

> **1. Publish inside a committing transaction.** `@ApplicationModuleListener` is `@Async` + `@TransactionalEventListener(AFTER_COMMIT)`. A `publishEvent` call with no active, *committing* transaction around it is silently dropped — Modulith never writes the `event_publication` row and the listener never fires. Every publisher must be `@Transactional`, or wrap the publish in a `TransactionTemplate` (see `ExpandUnitRunner`, which must query its slow source *outside* any tx first, then publish each result in a short tx). Publishing from a read-only or no-tx path is a defect. **A Modulith `Scenario` test wraps the publish in its own transaction and will pass even when the production publish site does not commit — so it is a false green. Every event flow needs a real-path test that drives the actual production publisher.**
>
> **2. Idempotent durable writes inside a listener must be DB-level upserts, never catch-based.** A listener runs its whole body in one transaction. On an IDENTITY-keyed table the INSERT executes eagerly, so a unique-constraint race throws `DataIntegrityViolationException` *and poisons the Postgres transaction* ("current transaction is aborted"). Catching it in Java does not un-poison the connection: any later statement in that tx — including Modulith's own AFTER_COMMIT completion write that marks the event handled — then fails, so the event is left incomplete and redelivered. Use `INSERT ... ON CONFLICT (...) DO NOTHING`, matching the constraint's exact columns/collation. This applies to *every* durable write a listener makes, not only multi-row loops.

Verification: every current publisher honors rule 1 (`ArtistActivationService.changeStatus`/`onSeedCreated`, `SettingsService.updateSettings`, `ExpandUnitRunner`). Rule 2 is honored by the two job enqueues (`insertIfAbsent`) but **violated by `CandidatePersistenceListener` (Finding D1).**

## Findings

### Design / SOLID

- **D1 [Important] `CandidatePersistenceListener` violates invariant rule 2.** `catalog/CandidatePersistenceListener` still does `existsByOwnerAndNameIgnoreCase` → `save` → `catch(DataIntegrityViolationException)` — exactly the pattern PR3b removed from the job enqueues. `artist` is IDENTITY-keyed, so on a real `(owner, name)` race the save poisons the listener tx, Modulith's completion write fails, and the event is redelivered (self-heals, but a spurious aborted-tx + redelivery every race). **Secondary bug:** the pre-check is case-*insensitive* but the DB constraint `artist(owner, name)` is case-*sensitive*, so "Radiohead" and "radiohead" for one owner can both land — the case-insensitive dedup is best-effort, never DB-enforced. **Fix (#95, scoped to the invariant bug):** DB-level upsert `INSERT ... ON CONFLICT (owner, name) DO NOTHING` against the existing `artist_owner_name_key` constraint — this removes the tx-poisoning (the Important bug). Keep the case-insensitive pre-check as a best-effort pre-filter, and the name-plausibility + `ArtistSource.valueOf` guards. **Deferred:** full case-insensitive DB-enforcement (a functional unique index `UNIQUE(owner, lower(name))`) is *not* done here because it requires de-duplicating any existing case-duplicate rows in the live DB — a data migration best done deliberately on its own (fold into #102 or a small follow-up). The case-insensitivity was already best-effort pre-#95, so this is no regression.
- **D2 [Important → resolved as removal] `location_fingerprint` is write-only dead state.** Written on enqueue/redue/backfill but never read for comparison; `onSettingsChanged` re-dues unconditionally; the Javadoc claims a stale-location detection that doesn't exist. **Decision: remove it** — drop the `scan_job.location_fingerprint` column (Flyway), the param on `insertIfAbsent`/`redueAll`, the backfill lookup, and `SettingsService.locationFingerprint`. (Bonus: this makes `ScanJob` and `ExpandJob` identical, which simplifies #94.)
- **D3 [Important → follow-up #102] Boundary smells `verify()` can't catch.** Expansion queries `catalog.ArtistRepository` for status/name that could ride on the event; `ScanUnitRunner` *writes* catalog's `Artist` aggregate (official-site-URL cache) from the `scan` module. **Deferred to #102** (carry `status` on `ArtistActivated`; expose a catalog `recordOfficialSiteUrl` method).
- **D4 [Minor] OCP seam: the "SEED-only source" rule is hardcoded as `== TRIBUTE_EXPANSION` in two places** (`ExpandJobListener`, `ExpandJobBackfill`). Adding another eligibility-restricted source means editing both. **Fix (folds into #94):** a `default boolean appliesTo(ArtistStatus status)` on `RelationSource`, overridden in `TributeLlmSource`; both callers become `if (!source.appliesTo(artist.getStatus())) continue;`.
- **D5 [Minor] Event Javadoc "Consumed by" lines are stale/wrong.** `SettingsChanged` says expansion (it's *scan*); `ArtistActivated` omits scan; `ArtistDeactivated` says "inert until PR3b". **Fix (#95):** correct or drop the hand-maintained lines.
- **D6 [Minor] `last_error varchar(255)` with hard truncation.** Both pollers truncate error messages to 255; API/LLM failures carry long bodies, so a parked job's stored reason is often a chopped fragment (full stack is in the logs). **Fix (#95):** Flyway `V?`: `ALTER COLUMN last_error TYPE text` on both tables; map with `@Column(columnDefinition = "text")` so `ddl-auto=validate` matches. Keep a generous truncation cap (~8000) to bound row size.
- **Not a problem:** `locationFingerprint`'s *input set* is correct (it hashes postal+radius+months; lat/long are derived from postal and read live at scan time) — the issue was that it's unused (D2), not its inputs. `shared.events` + primitive payloads + `shared` OPEN is the right call for this size (a dedicated `events` module is YAGNI). SRP/cohesion is good; no god-class.

### TDD / test quality

- **T1 [Important] The poller's optimistic-lock swallow path has no real-Postgres end-to-end test.** It's proven in two disconnected halves (a real-DB "stale save throws" repo test + a mock-repo "poller swallows the exception" test) but nothing drives a real concurrent `redueAll` against a real in-flight claimed job. This is the same "mocks can't reproduce a DB race" class the issue targets. **Fix (#95):** one `PollerFlowTest`-style test — claim a job, fire a real `redueAll`/`updateSettings` concurrently, run the reschedule, assert the DB reflects the re-due (not the poller's stale write) and `tick()` didn't throw.
- **T2 [Important] `CandidateDiscoveredFlowTest` uses the `Scenario.publish` false-green pattern** the incident was about, and is now redundant (the real-path proof is `PollerFlowTest.expandHappyPath`, which drives the real `ExpandUnitRunner` publish). **Fix (#95):** retire it (keep `CandidatePersistenceListenerTest`, the right layer for the guard/dedup branches).
- **T3 [Important] Deprecated `@MockBean` in 4 files / 6 usages; zero `@MockitoBean` adoption** (`JobEnqueueFlowTest`, `PollerFlowTest` ×3, `ScanJobBackfillTest`, `ExpandJobBackfillTest`). All are plain field-level single-bean mocks — drop-in swap to `org.springframework.test.context.bean.override.mockito.MockitoBean`. **Fix (#95).**
- **T4 [Minor → #94] Duplicated Testcontainers boilerplate.** 18 test classes copy the `PostgreSQLContainer` block; 14 also copy the OAuth `@DynamicPropertySource`; `awaitUntil` is duplicated verbatim in 2 files. No shared base test class exists. **A shared `AbstractPostgresIntegrationTest` (container + property source + `awaitUntil`) is a #94 deliverable.**
- **T5 [Minor] No `logback-test.xml`** to quiet the harmless Hikari/Testcontainers shutdown WARNs that noise every green build. **Fix (#95):** a minimal test logback raising `com.zaxxer.hikari`/`org.testcontainers`/`com.github.dockerjava` to ERROR.
- **T6 [Minor] Soft id-tautology in `ArtistActivationServiceTest`** (sets id via reflection, asserts the event carries the same object's id) — can't catch an id-mapping swap; but the real generated-identity flow is proven end-to-end by `JobEnqueueFlowTest`, so low risk. No action required (noted).
- **Strengths:** the real-path coverage is otherwise strong — `JobEnqueueFlowTest` covers activation/deactivation/settings-re-due/ON-CONFLICT-idempotency against real Postgres via the real listeners; `PollerFlowTest` covers the real expand publish→listener→DB path; `ScanJobRepositoryTest.claimDueIsSafeUnderConcurrency` is a genuine two-thread race. No false-green blanket-`any()` mock tests found.
